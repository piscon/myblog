> This article was machine-translated by AI and may contain inaccuracies. See the [Chinese original](/zh/posts/cf-auto-translate/) for the authoritative version.

This blog is multilingual (Simplified Chinese / Japanese / English). Previously, each language version was written manually, but as the number of articles increased, it became impossible to keep up. So I set up an automatic translation pipeline: after writing the Chinese version and pushing it, the Japanese and English versions are automatically generated and deployed within minutes.

## Overall Architecture

```
Push Chinese article
  → GitHub Actions (translate-content)
    → Call Cloudflare Workers AI for translation
      → Translate back to git
        → Netlify automatically builds and deploys
```

Key decisions:

- **Translation output is stored in git**, not generated temporarily during Netlify build. The translations can be reviewed, rolled back, and manually corrected. Netlify builds remain pure (always getting the final Markdown)
- **Use the free quota of Cloudflare Workers AI** (10,000 neurons per day), which is far more than enough for a personal blog
- **The visitor side is completely static**: The API key is only in GitHub Actions, no keys on the front-end, no additional requests, and no third-party scripts are loaded

## Model Selection

The free plan of Workers AI has a model whitelist, not all models can be used. Tested several options:

- GLM, DeepSeek series: Not available in the free plan (403), directly eliminated
- `llama-3.3-70b`: Can be used, but pure text translation will **miss entire sentences** (leaving some Chinese original text in a paragraph), not used
- `qwen3-30b-a3b-fp8`: Best quality for Chinese → Japanese, finally selected

## The biggest pitfall: Don't put Markdown into JSON

In the first version, to save time, I packed the title, summary, and content into a JSON and had the model return it as is. The result was that all fields were normal, but the link syntax in the content was broken:

```
Original file format:      [Hugo](https://gohugo.io)
JSON format output:        Hugo（https://gohugo.io）          ← Link is dead, becomes plain text
Plain text format output:  [Hugo](https://gohugo.io)          ← Syntax is preserved as is
```

Testing showed that both qwen3 and llama had this problem — not a problem with a specific model, but the format of "Markdown embedded in JSON string" is not friendly to the model, with too many escape layers.

Switched to a **two-step call**: fields (title/summary/category/tags) are short texts, and small JSON calls are fine; the main content is called separately as plain text. After that, links, lists, and code blocks are all preserved as is.

## Incremental: source_hash

Don't re-translate all articles every time push — it's expensive and more seriously, it would overwrite manually corrected translations. So each translated file's front matter contains a `source_hash`:

```toml
lang = 'ja'
title = '（Translated title）'
date = '2025-11-26'
draft = false
source_hash = '4bae5986e7a0…'  # sha256 of the Chinese source content, mixed with the version number of the prompt and model name
```

Rules:

- Hash matches → skip, **0 API calls**
- Chinese original content changes → hash mismatch → auto re-translate
- Change model → model name in hash changes → full re-translate

## Manual Protection Rules

- Translated files without `source_hash` = manually written, the script **never touches** them (neither overwrites nor deletes)
- After manual proofreading of machine-translated files, as long as the Chinese original content doesn't change, they won't be overwritten by re-translation
- If you don't want a single article to be translated: add `auto_translate = false` to the Chinese front matter
- When the Chinese source becomes a draft → the translated version is also taken offline; when the Chinese source is deleted → the translated file is automatically cleaned up

At the beginning of the machine-translated file, there is a blockquote declaration, with the original link, informing readers to refer to the Chinese original.
