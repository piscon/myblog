##  概要

大規模言語モデルは**機械翻訳**タスクにおいて実用的な閾値に近づいていますが、入力がMarkdown技術ドキュメントである場合、失敗のパターンは「翻訳が悪い」から「構造が破壊される」に変わります。リンクのターゲットが書き換えられ、リストの記号がアンカー本文に吸収され、コードブロックが吸収されてしまいます。このような損傷は文法エラーをトリガーしないものの、ページが静かに不正確になります。本論文では、このような問題を**文字空間の衝突**問題として形式化します。自然言語の翻訳空間とマシン文法のマークアップ空間が同じ文字列を共有しており、モデルがこれらを信頼できるように区別することができないからです[^1]。

## 2. 方法：プレースホルダの原子化

コアな考え方は、ドキュメントを2つの領域に分割することである。

| 領域の種類型 | 例例 | 処理方法式 | モデルに渡すか |
|---|---|---|---|
| マシン語法 | `[text](url)` の URL の部分 | 原子化置換换 | いいえ |
| スケルトン記号记 | `1. `、`## `、`\|` | 対ごとに保つ护 | いいえ |
| 自然語言 | 本文の段落、リンク文字 | 保つ留 | はい |
| コード块 | 囲み内のすべての内容 | 整塊置換换 | いいえ |

具体的な実装は、以下の擬似コードを参照すること（行内 `protectBody()` と `restoreBody()` がループを形成している）：

```python
def translate(body: str, lang: str) -> str:
    """保护 → 翻译 → 完整性门 → 还原"""
    protected, tokens = protect(body)   # «0» «1» …
    raw = model(protected, lang)        # 模型只见散文
    assert all(t.count == 1 for t in tokens)  # 完整性门
    assert skeleton_at_edges(raw)             # 位置门
    return restore(raw, tokens)               # 机械拼装
```
完全性ゲートチェックは3つのことを行います：各トークン ** は正確に1回 ** 、スケルトン `lead` / `tail` は行頭/行末に配置される、復元後の構造カウントは保存される。いずれかの項目が失敗すると再試行し、それでも失敗すればその記事はディスクに保存せず、古い翻訳文はその場に残されます。

## 3. 実験設定

検証は2段階で行われ、2段階目は外部サービスに依存しない：

- [x] オフライン自己テスト：全語彙の恒等往復 + 古い事故等価攻撃のブロック
- [x] 構造カウントフューズ：リンク、見出し、コードブロック、リスト項目の保存
- [ ] 実際のモデルによる長文ドキュメントのストレステスト（本記事がその層の入力となる）
- [ ] 多言語レンダリング一貫性の比較

ここで「古い事故等価攻撃」とは、人為的に以下の損傷を作成し、ゲートがブロックできることを検証することを指します：

1. `lead` マークが文の間に移動されている
2.  終了アスタリスクが行中に移動されている
3.  トークンが削除されたり、重複したり、越境番号が偽造されている
   -  削除と重複が完全性ゲートをトリガーしている
   -  越境番号の偽造が直接拒否されている

## 4. 議論

### 4.1 なぜ二重チャネル相互検証を使用しないのか
二回の独立した呼び出しはランダムな損傷を低下させますが、**システムエラー**には効きません。同じモデルが同じ組み合わせ構造に直面すると、常に同じ間違いを安定して行い、結果が一致しているため、同じように許可されます。これは「**安定性がトークンの節約よりも重要**」という制約と矛盾しないのです――ボトルネックは予算ではなくアーキテクチャです。

### 4.2 境界条件

正文若含字面量 `«1»`（书名号、法文引号或随手输入），会被 token 正则误认成占位符，导致越界与永久失败。修法是把 `«n»` 字面量与孤立 `«`/`»` **一并原子化**，使模型输入中唯一的 `«n»` 都是真编号。这提示一个更一般的原则：占位符字符集必须与自然语言字符集**完全隔离**，或由保护 pass 保证其唯一性，而不能仅靠「选个罕见字符」的赌注。

### 4.3 コンテンツ管理システム（CMS）との関係

入力バウンダリ（CMSの富文本エディタ）は通常のMarkdownを出力すればよい。保護層はパイプライン内部に位置し、フロントマターのフィールドを追加せず、schemaを変更しない。歴史的にCMSとの往復において`*斜体* [链接](url)`の構造を保証しているため、入力側の調整は必要ない。 

## 5. 結論
信頼性を「モデルが従うかどうか」から「モデルが文法に触れられない」ことに移すことで、リンクを分解し、タグを飲み込む2つの事故を**確率事象**から**アーキテクチャ上不可能な事象**に低下させることができる。その代償は、約100行のコードの保護と、一度のフルリトランスレート（プロンプトバージョンの不一致）である。得られる利点は、プロンプトを非常に簡潔にでき、失敗した場合でも古いコンテンツがその場に残り、オンライン上では損傷したページが一切表示されないということである。
