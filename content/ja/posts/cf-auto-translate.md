> 本記事はAIによる自動翻訳です。表現が不自然な場合は[中文の原文](/zh/posts/cf-auto-translate/)をご参照ください。

このブログは三語対応（簡体中文 / 日本語 / English）で、以前は各言語バージョンを手動で作成していました。記事数が増えるとどうしても追いつかなくなるため、自動翻訳パイプラインを構築しました。中文記事をpushすると、数分以内に日本語版と英語版が自動生成され、自動デプロイされます。

## 全体構成

```
中文記事をpush
  → GitHub Actions（translate-content）
    → Cloudflare Workers AIを呼び出して翻訳
      → 翻訳結果をgitに書き戻す
        → Netlifyが自動ビルド・デプロイ
```

いくつかの重要な決定事項：

- **翻訳結果をgitに保存**し、Netlifyビルド時に一時生成しない。翻訳結果はレビュー・ロールバック・手動修正が可能で、Netlifyビルドは純粋な成品Markdownを取得するだけ
- **Cloudflare Workers AIの無料枠を使用**（毎日10,000 neurons）。個人ブログの翻訳量では十分すぎる
- **訪問者側は完全な静的サイト**：API keyはGitHub Actions内にのみ保管。フロントエンドには秘密鍵や追加リクエストが一切なく、サードパーティスクリプトも読み込まれない

## モデル選定

Workers AIの無料プランにはモデルホワイトリストがあり、すべてのモデルが利用できるわけではありません。いくつかのモデルをテストしました：

- GLM、DeepSeekシリーズ：無料プランでは利用不可（403エラー）で除外
- `llama-3.3-70b`：利用可能だが、純テキスト翻訳で**文の一部が漏れる**（一部の文が中国語のまま残る）ため使用不可
- `qwen3-30b-a3b-fp8`：中国語→日本語の品質が最も良いため最終的に選定

## 最大の落とし穴：MarkdownをJSONに詰めない

初版では手間を省くために、タイトル・要約・本文を1つのJSONにまとめモデルに送信し、結果をそのまま戻す方式を採用しました。その結果、すべてのフィールドは正常でしたが、本文内のリンク構文が破損しました：

```
元ファイルの記述：      [Hugo](https://gohugo.io)
JSONモードの出力：   Hugo（https://gohugo.io）          ← リンクが死んでテキストに
純テキストモードの出力：  [Hugo](https://gohugo.io)          ← 構文がそのまま残る
```

qwen3とllamaの両方でこの問題が発生しました――特定のモデルの問題ではなく、「MarkdownがJSON文字列内に含まれる」形態自体がモデルにとって不向きで、エスケープレベルが多すぎるためです。

**2段階呼び出し方式**に変更：フィールド（タイトル/要約/分類/タグ）は短文で、小規模なJSON呼び出しで問題なし。本文は別途純テキスト呼び出しで行う。これによりリンク・リスト・コードブロックがすべて元のまま保持されるようになりました。

## インクリメンタル：source_hash

すべての記事を毎回再翻訳するのは無駄で、特に手動修正済みの翻訳を上書きしてしまう危険があります。そのため各翻訳ファイルのfront matterに`source_hash`を保存しています：

```toml
lang = 'ja'
title = '（翻訳後のタイトル）'
date = '2025-11-26'
lastmod = '2026-11-05'
draft = false
source_hash = '4bae5986e7a0…'  # 中文原稿のsha256、ヒントワードバージョン番号とモデル名を含む
```

ルール：

- hashが一致 → スキップ、**API呼び出し0回**
- 中文原稿が変更 → hashが合わない → 自動再翻訳
- モデルを変更 → hash内のモデル名が変わる → 全量再翻訳

## 人間による保護ルール

- `source_hash`のない翻訳ファイル = 人間が手書きした物で、スクリプトは**絶対に触らない**（上書きも削除もしない）
- 機械翻訳ファイルを人間が校正後、中文原稿が変更されなければ再翻訳されない
- 特定の記事を翻訳したくない場合：中文front matterに`auto_translate = false`を追加
- 中文原稿が下書き状態 → 翻訳ファイルも同期して非表示に；中文原稿が削除 → 翻訳ファイルが自動で削除

機械翻訳ファイルの冒頭には引用ブロックで声明を記し、元の中国語記事へのリンクを付けて、読者に中国語原稿を基準としていることを伝える。

## この記事がパイプラインの最初の実戦

現在読んでいる中国語版は私が書いたものです；日本語版と英語版は、この記事をpushした後にパイプラインが自動生成・自動デプロイしたものです。ページ上部の言語切り替え器で三語版を読めば、全体のフローが正常に動作していることを確認できます。
