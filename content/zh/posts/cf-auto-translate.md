这个博客是三语的（简体中文 / 日本語 / English）。我写完中文 push 上去，日文版和英文版几分钟内自动生成、自动部署上线——中间没有任何人工翻译的环节。这篇文章用大白话讲清楚它是怎么运作的，以及过程中踩过的坑。

## 一、整体长什么样

整条流水线跑在 GitHub Actions 上，全部用免费资源：

```
写完中文文章 push
  → GitHub Actions 触发翻译
    → 调 Cloudflare Workers AI（免费额度）
    → 译文先过几道自动检查
    → 检查通过，机器人提交回仓库
      → Netlify 自动部署，日/英文版上线
```

动手之前定了四条规矩，后来证明每条都救过命：

- **译文进 git**。日文英文版是仓库里的真实文件，随时可以打开看、可以改、可以回滚。AI 只是「初稿作者」，不是发布通道
- **访客侧完全静态**。API 密钥只存在于 GitHub Actions 里，网页上零密钥、零第三方脚本，读者不会为我多用一度电
- **每次调用都有账单**。所有请求经过 AI Gateway，花了多少 token、折多少钱、耗时多少，一条条记着
- **部分失败不拖垮整体**。日文翻成功了、英文翻挂了，那就日文先上线，英文留着旧版等重试

## 二、核心难题：AI 会把 Markdown 翻烂

让 AI 翻译纯文字，效果已经很好。但博客文章不是纯文字——它混着链接、代码块、表格、列表标记。早期直接把整篇 Markdown 扔给模型，翻出来的东西经常「看着像对的」，实际上烂掉了。真实案例：

```
原文：1. *感谢 [Hugo](https://gohugo.io) 提供代码支持*
翻后：[1. *Hugo](https://gohugo.io)に…（列表标记和星号被吞进了链接文字）
```

最坑的是这类损伤**不会报错**——链接还是那个链接，页面照样渲染，不仔细看根本发现不了。光靠在提示词里写「请保持格式」，实测没用：模型看得见语法，就忍不住要动语法。

最后用的办法很直接：**别让 AI 看见语法**。

翻译之前，程序先把文章「拆开」：代码块、链接地址、行内代码、各种标记符号，全部替换成 «0» «1» 这样的编号占位符。AI 看到的只剩纯中文句子加几个编号，它想破坏语法也无从下手。翻完之后程序把占位符原样换回去。

拆分用的是 Markdown 解析器（remark）按语法树定位，而不是正则表达式硬匹配——解析器认识所有规范语法，以后出现新语法也不用打补丁。翻完还有几道自动检查：

1. **编号完整性**：每个占位符必须恰好回来一次，少了、多了、重复了都算失败
2. **位置检查**：列表标记必须还在行首，收尾符号必须还在行尾
3. **结构比对**：译文和原文的链接数、标题数、表格数必须一致

检查不过就自动重试；还是不行就把这一段切小了重翻；再不行，单行原样保留——一行没翻译，好过整篇是坏的。

## 三、省钱机制：改多少，翻多少

每个译文文件带两个「指纹」（hash），一个对应正文，一个对应标题摘要这些字段：

```toml
source_hash = '…'        # 正文的指纹
source_fields_hash = '…' # 字段的指纹
```

翻译前先比对指纹：

- 改了**正文** → 只重翻正文，标题摘要沿用旧的
- 只改了**摘要或标签** → 只重翻字段，正文分文不花
- 什么都不变 → 零次调用（每周日凌晨的定时对账就是这样全量扫描一遍，干净时一分钱不花）

另外 Cloudflare 的 AI Gateway 自带 7 天缓存：同样的请求第二次问，直接返回上次的答案，不计费。所以修一个错别字推上去，往往只需要花真正变了的那部分的钱。

实测数字：免费计划每天 10,000 neurons（Cloudflare 的算力计价单位），一篇三千字文章翻一个语言大约 50-160 neurons——一天翻十几篇也用不完。

## 四、中文摘要也归它管

有时候写完文章忘了填摘要。流水线发现中文文章没有 `description`，会自动按正文内容补写一段 70-160 字的摘要，写回文章文件。三个语言的摘要都以这段为源头翻译——**三语摘要永远说的是同一件事**。之后你在 CMS 里手改摘要保存，三语自动跟着更新。

## 五、人永远有一票

自动化最容易走偏的方向是「机器全自动，人没法插手」。这条流水线给人工留了完整的接手路径：

- 在 CMS 里给某篇译文勾**「锁定译文」**：这份译文从此视同人工稿件，永不覆盖、永不删除，中文原文更新也不再同步
- 在 CMS 里给中文文章勾**「不翻译」**：这篇直接退出流水线
- 校对过的机翻不会被无脑重翻：只要中文原文对应部分没动，指纹就没变，就不会花钱重译
- 生命周期自动同步：中文文章删除，译文跟着清理；中文转草稿，译文跟着下架

## 六、踩过的坑（如果你也想搭一套）

几个花真金白银（和时间）换来的教训：

- **速率限制要主动适配**。Cloudflare 的限流比文档上写的更容易触发，客户端固定放慢请求速度（每 2 秒一个）比事后退避省心得多
- **别让 AI 用 JSON 格式输出正文**。Markdown 塞进 JSON 会被模型拆得七零八落，正文必须走纯文本
- **失败时宁可保守**。译文存疑就不发布，旧版继续挂着，等下次重试——静态博客的「旧」远没有「坏」致命
- **每道防线都要有离线自测**。这套系统的检查逻辑有几十条断言，每次改动跑一遍，零 API 消耗

## 七、这篇就是活样板

你现在看到的日文版和英文版，就是刚才这次 push 之后几分钟内自动翻译、自动部署的。切到页头的语言切换器对比着看——AI 翻得自然与否，一眼便知。
