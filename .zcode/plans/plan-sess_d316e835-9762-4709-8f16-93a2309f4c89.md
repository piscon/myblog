# AI 翻译多语言内容（Cloudflare Workers AI 免费额度）

## Context
博客三语（zh/ja/en），翻译覆盖率极低（3 篇中文仅 1 篇有日英文版），人工维护三语负担重。目标：push 中文文章后由 CI 自动生成/更新日文、英文版，走 Workers AI 免费额度，译文直接上线并在文首附机器翻译声明。部署链不变：`push master → Netlify 自动构建`。

## 架构（复用 update-lastmod.yml 先例）
```
push master (content/zh/**) → translate workflow → scripts/translate.mjs 调 Workers AI
  → 写 content/{ja,en}/posts/<同名>.md → hugo 构建校验 → github-actions[bot] 提交（[skip-lastmod]）→ push → Netlify 部署
```

## 实施步骤

1. **获取 CF 凭据**（用户指定的第一步）：用 `cf` 命令查看可用能力，获取/确认 API token（Workers AI run 权限）+ account id（已在 `.cloudflare/cache/cloudflare-account.json`：`ac9945...`）；`cf`/API 列出 text-generation 模型，选定中→日/英翻译用模型（默认候选 `@cf/meta/llama-3.3-70b-instruct-fp8-fast`，以实际列表为准）
2. **GitHub Secrets**：`gh secret set` 写入 `CLOUDFLARE_ACCOUNT_ID`、`CLOUDFLARE_API_TOKEN`（token 不进 git）
3. **`scripts/translate.mjs`**（node ≥20，零依赖，仅用全局 fetch）：
   - 扫描 `content/zh/posts/*.md`，跳过 `_index.md`、`draft=true`、`auto_translate = false` 的文件
   - 增量控制：对译文相关内容（body+title+description+categories/tags+cover.alt/caption）算 sha256，与目标文件 front matter 里的 `source_hash` 比对——一致则跳过，不一致才调 API（费用只在内容变更时发生）
   - 每文件每目标语言一次 chat 调用，要求返回 JSON（title/description/categories/tags/cover_alt/cover_caption/body），front matter 由脚本组装（LLM 不碰文件结构）；date/cover.image/weight 等字段原样复制
   - 源文删除→删机翻目标文件；源文转 draft→目标 draft=true（人工手写的译文无 source_hash，永不删除/覆盖）
   - 译文文首插入 blockquote 声明：「本文由 AI 翻译自[中文原版](/zh/posts/<名>/)，如有歧义以原文为准」（ja/en 各自措辞）
4. **`.github/workflows/translate-content.yml`**：仿 update-lastmod.yml——push master + `paths: content/zh/**` + workflow_dispatch（首次回填用）；concurrency 串行；`contents: write`；跑脚本 → `hugo --gc --minify` 校验产物 → bot 提交，提交信息带 `[skip-translate] [skip-lastmod]`（防循环 + 省 workflow 次数，符合 AGENTS.md 配额节俭）；自己的 push 不触发自己（path 只看 zh）
5. **本地回填**：直接跑一次 `scripts/translate.mjs`，给现有 2 篇未翻译文章生成 ja/en 版，检查质量后一并提交
6. **AGENTS.md 补记**：内容约定区新增 AI 翻译流水线说明（触发、增量机制、opt-out 字段、机翻声明、人工校对不会被覆盖的条件）

## 不做的事
- 不动 hugo.toml/.pages.yml/layouts（零模板工作，层级 1）；feature-check 无需新断言（不依赖主题 DOM）
- Netlify 侧不配置任何东西；一次内容变更会触发两次部署（原文 push + 译文 push），可接受

## 验证
- 本地：`node scripts/translate.mjs` 生成译文 → `hugo --gc --minify` 构建通过 → 检查 ja/en HTML 的 hreflang 三语互链
- 推送后：`curl https://deux.top/ja/posts/<名>/`、`/en/posts/<名>/` 确认线上渲染（按 AGENTS.md 用 curl 不耗 GitHub API）；`sleep N && gh run view` 单次核验 workflow 结果
