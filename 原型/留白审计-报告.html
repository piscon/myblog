整体合理度约七成：页面框架（沟槽、阅读列、触控）站得住，真正的问题不是「多几像素少几像素」，而是同一个关系有 3–5 个不同的值，以及三处会把结构读错的硬伤。

必修的三处：① 首页「近作」首图 404，撑出 409px 空洞；② 文章页 / 留言板 / 搜索页的最后一个带边框的块与页脚线 0px 相接；③ 正文里表格 28px、列表 25.2px，比段落 27px 还紧——最重的块最挤。

二、正文块间距：层级是倒的

段落 p27
列表 ul / ol25.2
表格 table28
代码块 pre（无包裹）28
代码块 .code-block36
图片 figure44
引用 blockquote46.2
h2 上间距70

根因：外边距写成 em，而 em 按元素自身字号算。table / pre 是 14px → 2em = 28px；ul 是 1.4em = 25.2px。于是「越大的块越挤」，和视觉重量完全相反。

01P0近作首图 404，撑出 409px 空洞

  • 证据：assets/market-morning-5c2f.jpg 返回 404（磁盘上是 5b2f）。图片盒 613.7×409.1 仍占位，naturalWidth=0，桌面 916.8→1325.9、手机 997.5→1406 全空。
  • 为什么算留白问题：这是首页折叠线下方最大的一处「什么都没有」，读者看到的是 400px 空白后才出现标题，而不是一张图。
  • 改法：main.js.txt 数据里 5c2f → 5b2f（一处错字）。改完首屏闭合，后续所有关于「近作」的留白判断才成立。

02P0页尾 0px：最后一个盒子压在页脚线上

  • 证据：文章页 .giscus-shell 底 5475.9 = 页脚顶 5475.9；留言板同值；搜索页 .tag-hub 底 1985 = 页脚顶 1985。两条 1px hairline 叠成 2px 粗线。
  • 对照：首页/列表/归档/关于/标签索引的尾空都是 96px（实测 101–117）。三种视图属于「漏了 padding-bottom」，不是设计选择。
  • 改法：.comments{padding-bottom:96px}（文章 + 留言板共用），.tag-hub{padding-bottom:96px}；≤768px 统一 72。

03P0表格只比段落松 1px

  • 证据：段落 27、列表 25.2、表格 28、代码 36/28（是否被 JS 包 .code-block 决定）、图 44、引用 46.2。
  • 为什么错：表格是四列数据块，视觉重量最大，读数时需要「停一下」；现在它和正文段落的间距几乎相同，读起来像段落还没结束。列表则比段落更紧，看起来像「贴着上一段」。
  • 改法：table/pre/.code-block 改 40，ul/ol 改 28，图与引用取 48，段距 28。

04P1章节间距有 5 个值，没有标尺

  • 证据：首页 150 / 110、列表年份间 105、文章段落→h2 80、搜索结果→标签云 89.5。同一「章节分隔」相差近一倍。
  • 根因：每个容器各自写死（hero pb 92、recent pt 26 pb 78、ledger pb 96、year-group pt 58）。
  • 改法：引入一个 --sp-section（桌面 96 / 手机 72），所有章节上边距改由它承担；.section-head 的 22px 保留（这是「线到标题」的固定值，本来就没漂）。

05P1页首一页一个样，且存在双重留白

  • 证据：文章 58、列表/关于/标签/留言 80、搜索 85——文章页页首比列表页少 22px。列表页 .page-head pb 34 + .filters mt 34 = 68 的「两个 34 相加」，关于页 pb 34 + grid pt 40 = 74。
  • 为什么错：同一层级的两个容器各出一半间距，谁改都会牵动另一处，是留白漂移最常见的来源。
  • 改法：页面首部统一 padding-top:64px（手机 48），下边距归零，交给下一个块的 margin-top 单独负责。

06P1筛选条：上 17、下 59，文字贴着上边线

  • 证据：列表页筛选文字距上边线 17、距下一条线 59；搜索页同一组件是 17 / 33。文字在带内明显偏上。
  • 改法：.filters 改 padding:16px 0，下方由下一区块的 40 承担——两条线之间变成 16 / 40，不再是 17 / 59 与 17 / 33 两种。

07P2音频图注被行盒顶开一倍

  • 证据：audio 底 1817.9 → figcaption 顶 1840.1 = 22.2px，而 CSS 声明的是 margin-top:11px。多出的 11px 来自 inline 元素的基线下沉。
  • 改法：.media-embed audio{display:block;margin-top:0}。顺带消掉整块 11px 的虚高。

08P21px 漂移与「没有标尺」

  • 证据：.recent-item 19/20、.post-row 18/19；连续 10 行会累积出 10px 的错位。首页在用的 margin/padding 共 23 个不同值，只有 8 个落在 4px 栅格。
  • 改法：成对 padding 取同值（19/19 或 20/20，18/18）；把下列 token 落成 :root 变量，新增样式只许取值不许写裸数。

四、修复清单（按顺序，改完即生效）

/* P0-1 */ main.js.txt: market-morning-5c2f.jpg → market-morning-5b2f.jpg /* P0-2 页尾闭环 */ .comments { padding-bottom: 96px; } .tag-hub { padding-bottom: 96px; } @media (max-width:768px){ .comments,.tag-hub { padding-bottom:72px } } /* P0-3 正文块间距（去掉 em 的字号陷阱） */ .article-body > p { margin: 28px 0; } .article-body ul, .article-body ol { margin: 28px 0; } .article-body table { margin: 40px 0; } .article-body pre, .article-body .code-block { margin: 40px 0; } .article-body blockquote { margin: 40px 0; } .article-body figure { margin: 48px 0; } /* P1-4/5 章节与页首 */ :root { --sp-section: 96px; --sp-head: 64px; } .hero { padding-bottom: var(--sp-section); } .recent { padding: 0 0 var(--sp-section); } .ledger { padding-bottom: var(--sp-section); } .page-head,.search-head { padding-top: var(--sp-head); padding-bottom: 0; } /* P1-6 筛选带 */ .filters { margin-top: 48px; padding: 16px 0; } /* P2-7 音频 */ .media-embed audio { display: block; margin-top: 0; } /* P2-8 1px 漂移 */ .recent-item { padding: 20px 0; } .post-row { padding: 18px 0; }

前三条是硬伤，改完页面不会「变样」，只会「变对」；后五条是节奏归一，会有可见的松紧变化，建议一次只改一类，改完在 1440 / 390 各看一眼。

六、顺带看到的两处（非留白）

手机端 .article-deck 被压到 16px，而正文是 18px——导语比正文还小，层级反了；桌面导语是 18px 与正文等大。若要保留层级，手机端导语应 ≥18px，或把正文降到 17px。
另外 320px 下文章页眉题（分类 · 日期 · 时长）会折成两行，把标题整体下推 24px——不是错误，但若想守住单行，可以在这档隐掉「时长」。
