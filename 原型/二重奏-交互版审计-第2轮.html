02已修复

每条都给证据与复验方式，不留“应该好了”。

P0语言切换器被收进汉堡，而头部明明有 136px 空档

证据。≤860px 有一条 .lang-wrap{display:none}，语言只能进汉堡面板（文章 / 关于 / 简体中文 日本語 English）。而实测 390px 下：品牌右缘 94px、搜索图标左缘 230px——中间空了 136px；320px 下同样空 66px 且仍能容下第四个 44px 图标。

改法。语言 globe 在所有宽度常驻头部（与搜索/主题/汉堡同款 44px），汉堡面板只留站点导航；≤860px 时下拉面板锚定 .head-actions 而非 44px 按钮，196px 宽在 320px 也不会从左边出界；当前语言沿用桌面同款金色对勾；两个面板互斥。

复验（真实浏览器）。320px：🌐118–162 · 🔍164–208 · 🌙210–254 · ☰256–300，右侧留 20px，scrollWidth = 320；390px：🌐184–228 · 🔍230–274 · 🌙276–320 · ☰322–366；面板展开后 x=170.3 / right=366.3，完整在视口内。860 / 1440 无溢出。开汉堡→语言自动关闭，开语言→汉堡自动关闭，aria-expanded 双向同步。

P1正文里 9 处 Markdown 标记没渲染，读者直接看到星号

证据。扫描全部 10 篇正文：zz-s04 / zz-s05 / zz-s07 与 cf-auto-translate 里有字面量 **「送到」…**；zz-s01 / zz-s02 / zz-s03 / zz-s06 里有字面量 *后来那盆绿萝…*。页面渲染成一串裸星号，正文语气全被破坏。

改法。代码块（<pre>）内原样保留——那里是「AI 把 Markdown 翻烂」的示例，星号必须留；其余全部转成 <strong> / <em>。复验：代码块外残留 0 处。

P1汉堡面板打开时锁死整页滚动，却没有焦点陷阱

证据。面板只有 198px 高（下拉，不是模态），但 setMenu() 里写着 document.body.style.overflow = 'hidden'。结果：页面冻住不能滚，键盘 Tab 却能一路走出面板到被冻住的正文里——两头都别扭。改法。去掉滚动锁，给面板 max-height: calc(100dvh − 68px) + 自身滚动 + overscroll-behavior: contain（将来加菜单项也不会把尾巴顶出屏幕）。

03待你拍板

这些不是 bug，是设计决定；但落地前不定，站上就会长成两套。

项现状影响 / 建议
断点交互版 860，站点 768860 会让 iPad 竖屏（820 / 834）也进手机布局：品牌缩水、导航收进汉堡。建议跟站点统一到 768，或明确「平板算手机」。
目录侧别交互版浮动在右，站点在左两套阅读路径。站点现行是左浮动（translate(-100%,-50%)），改右侧要重算与内容列的间距。

字号下限文档写「元信息 12px 下限」实际仍有 .brand-en 8px、.year-label small 11px、标签计数 10px。要么补进 12px 规则，要么把政策改成「标签类可到 10px」。
字号阶梯共 15 级，含 11.5 / 14.5 / 17.5近邻级差常低于 5%，肉眼分不出，只增加维护成本。建议收敛到 9–10 级，去掉半像素值。
中文衬线回退display 栈未按语言分栈Windows 上汉字落到 SimSun（笔画细、气质老），与 mac 的 Songti 差很远。§5 已列 ja/en，zh 也要补。
hreflang 取值原型写 zh-CN站点由 Hugo 按语言码输出（zh）。落地时以 head 的 link[rel=alternate] 为数据源即可，原型标注建议对齐。
文档里 5 个 h1每个视图各一个，靠 hidden 隐藏落地到 Hugo 每页只有 1 个，无碍；作为交付稿建议注明，免得接手的人当成错误。
