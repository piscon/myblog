01结论

这是一份完成度很高的视觉提案，也是一份不能直接上线的实现原型。最强的地方是把「二重奏」翻译成「页边」：正文是一个声部，日期、图注和留白是第二个声部。暖纸、宋体标题、单一铜金、无卡片无阴影——整页的呼吸感是成立的，读起来像一本安静的册子，而不是又一个 Hugo 默认皮肤。

但它是用一套单页应用模拟出来的：五个视图在同一个 HTML，内容由 JavaScript 注入，URL 是 hash。Hugo 站点需要的静态 URL、SEO、无 JS 可达、三语入口、分类/标签页、搜索页的分类中枢、TOC、评论，都没有在这份稿子里落地。原型可以这样演示；站点不能这样实现。

建议：视觉方向通过，按 8 个决策拍板后，用 Hugo 静态模板重写落地层。不要把 SPA 结构搬进 PaperMod。

02做得好的

  • 概念是可解释的。「页边」不是装饰词：日期、图注、署名都真的挂在正文之外，形成第二个声部；文章页的图注尤其成立。
  • 字体与颜色克制。宋体标题 + 无衬线正文 + 等宽元信息，暖纸底 + 青铜金；没有渐变、没有卡片阴影、没有 emoji。强调色只出现在圆点、引用边、筛选下划线、搜索高亮。
  • 首页有编辑节奏。「特稿—近作—目录」三段，一大一小、一图三文，避免了三张等宽卡片的模板感。
  • 文章页的正文处理成熟。标题、正文、表格、任务清单、代码块、引用、页边图注都有对应排版；表格与清单没有掉队。
  • 状态完整。明暗双主题、390/900/1440 三档无横向溢出；菜单、搜索、Ctrl/⌘+K、筛选、阅读进度、复制链接都实测可用。
  • 用的是真内容。文章、标题、摘要、关于页文案来自现有站点，不是 Lorem Ipsum；这使节奏判断是可信的。

03P1 阻断项

这些不是审美问题，是「照这份稿子实现会坏」的问题。按落地风险排序。

P1

单页应用不是 Hugo 站点的落地结构

这份稿子把五个界面写进一个 HTML，用 hash 路由切换；它证明了视觉，但不能证明站点。

证据5 个 data-view；URL 形如 #/posts/zz-s03；#view-posts 源码里 0 行、0 图；文章正文在 JSON 里；<noscript> 明确写着需要 JavaScript。

影响：关闭 JS 只剩首页 hero；文章不能独立索引、分享、被 RSS 收录；Hugo 的分页、taxonomy、hreflang 全部被 hash 路由替代。

建议：视觉层保留，结构改成 Hugo 静态模板（index.html / _default/list.html / single.html / search.html）；JS 只做主题、菜单、搜索、进度；文章 URL 用 /posts/<slug>/。

P1

语言、分类、搜索中枢与导航被简化掉了

这是一份「单语、单入口、单层目录」的稿子；站点是三语、有 taxonomy、有搜索分类中枢、有留言板的。

证据hreflang 0 处；页头没有语言入口；分类全是 <span>，没有 <a href>；标签链到搜索而不是 tag 页；搜索页没有分类/标签聚合；导航是「文章 / 搜索 / 关于」+ 搜索图标（搜索出现两次）；页脚没有留言板/归档。

影响：三语入口、分类/标签页、搜索页的分类中枢、留言板全部丢失；与站点 2026-11-06「搜索脱离导航菜单」、taxonomy 与分类链接约定直接冲突。

建议：语言 globe + hreflang；分类/标签恢复真实 <a href>；搜索页恢复分类/标签聚合；导航改「文章 / 归档 + 搜索图标」；页脚补留言板。

P1

列表页和刚定稿的 Casper 堆叠卡相反

这版列表是一条很漂亮的文字目录，但它推翻了站点 2026-11-07 刚拍板的 image-top 堆叠卡。

证据.post-row 是 98px / 1fr / 62px / 58px 的纯文字行；#view-posts 源码 0 个 <img>；站点现行列表是 1.818 封面、26/800 标题、16px 三行摘要、4.8vmin 卡距（手机 40px）的 Casper 卡。

影响：列表失去图文身份，与用户刚签认的方向相反；brief 的「图文内容」只剩首页与文章页。

建议：三选一。(a) /posts/ 保留 Casper 卡，这版 ledger 作为 /archives/；(b) ledger 每行加 96–120px 封面缩略图，保留目录感；(c) 明确拍板全站改文字目录。推荐 (a) 或 (b)。

P1

680 宋体 vs 720/18 无衬线：阅读系统要拍板

设计的阅读列比站点现行正文窄 40px，标题从无衬线换成了宋体；这是一次系统级改动，不是样式微调。

证据--measure: 680px；站点正文 720px / 18px = 40 个全角字，AGENTS 标注「勿动」；设计标题用 Songti / Palatino；ja/en 没有对应的衬线栈。

影响：落地会改黄金字阶与行长契约；ja/en 标题可能落回中文字体，三语版面不一致。

建议：拍板 680 还是 720（680 在 WCAG 内，但需重新签认）；补 ja/en 衬线栈（Yu Mincho / Hiragino Mincho / Noto Serif JP；Iowan / Georgia），三语实机看标题。

P1

长篇阅读缺 TOC、更新于、评论

文章页只做到「好看地读完」，没有做「读完之前怎么找、读完以后怎么接」。

证据源码 0 个 toc；文章 kicker 只有分类/日期/时长；0 个 giscus；站点 showtoc = true、更新于在首屏 meta、「相关文章 → 评论」的顺序已定。

影响：长文没有目录；有时效的文章失去「更新于」；评论区缺失。

建议：把 TOC 放进「页边」：≥1200px 显示在 margin，≤1199px 折叠到标题下；补「更新于」（lastmod > date+1d）；相关文章后接 giscus。

P1

触屏 hover 全部裸露

这份稿子有 23 个 :hover，但没有一个 @media (hover:hover) 门控。

证据正则统计 23 个 :hover、0 个 @media (hover:hover)；站点 2026-11-06 有「分享按钮金态在触屏上粘住」的实测事故，并已把 5 条反馈统一门控。

影响：触屏点按后下划线、金色、图片缩放会粘住，直到点空白；这与站点现有的 62 项断言直接冲突。

建议：所有非必要 hover 包进 @media (hover:hover)；键盘保留 :focus-visible；代码复制按钮按站点既有例外处理。

P1

内容规则与图片资产未定

首页的「特稿 / 近作 / 目录」是这份稿子的灵魂，但它是三段硬编码，不是一套可运营的规则。

证据ORDER 与 META 硬编码；6 篇阅读时长与站点实际值不符（见证据表）；0 个 srcset；配图是设计示意而非文章真实封面；站点 cover.html 已统一 720px / 100vw 的 srcset。

影响：CMS 无法决定 lead/近作/目录；错误时长会直接上线；手机下载 300–470KB 的大图。

建议：定义 lead/近作/目录规则（weight/featured + 回退）；改成真实阅读时长；换真实/有授权照片；用 Hugo image processing 出 srcset。

05P3 打磨

  • 近作右列与封面底部不齐。7 列封面约 427px 高，右列三条约 210px；底部空档约 200px。可底部对齐、补第四条，或把右列改成 2×2。
  • 英文标题 tracking 偏松。当前 -0.005em；英文 display 建议 -0.02em 左右，CJK 保持 0。
  • 关于页「写作者」。站点 about 没有职业标签；要么删掉，要么确认这是可对外的事实。
  • 「Search · 站内」中英不配。可改「Search · 搜索」或「站内搜索」。
  • 打印深色不完整。@media print 只改了 body 颜色，未重置 tokens；深色模式打印可能低对比。
  • 图片宽高属性过时。HTML 写 2000×1333，实际文件 1800×1200（比例相同，CLS 不受影响，但值应一致）。
  • .mm-langs 的 aria-label。加在普通 div 上不会稳定暴露；改 role="group" 或去掉。
  • theme-color 首帧。meta 初始是浅色，深色模式首帧可能闪一下；把判断放进 head 的首帧脚本。

06落地决策

在动手写模板前，需要拍板这 8 件事；否则实现会在半路遇到互相冲突的约束。

  • 列表形态：Casper 堆叠卡 / 文字目录 / 混合（推荐 a 或 b）
  • 正文系统：680 宋体 / 720 无衬线；选一个并签认
  • 首页选文：weight / featured / 最新；定义 lead / 近作 / 目录的规则
  • 语言入口：header globe + 下拉 / 只放页脚；选一个
  • TOC：页边悬浮 / 标题下折叠 / 不做；长文建议前两者
  • 评论与留言板：本期保留 giscus / 延后；两者都不做需说明
  • 图片：真实照片清单、授权、srcset 尺寸；替换当前设计示意
  • 实现：Hugo 静态模板 + 渐进增强，不做 SPA / hash 路由
